# 2026-10-27 · 内存选型与系统镜像工作站定位

## 内存选型

用户决定：**沿用当前这款内存选型**。本机当前 8GB 配置在信步主板、Ubuntu 24.04 / `7.0.14-xyzbox-rt` 组合下，本次未发现与内存选型有关的稳定性问题。

证据：在线分配 5120MiB，4 线程，连续 10 小时；0 hardware incidents、0 errors，正常退出；CPU 封装温度每分钟采样峰值 62°C。
本次结果支持继续采用当前配置，覆盖范围是已测机器、内存与这套负载；没有将它写成全批次或全部物理地址的检测结论。
厂商、料号、频率等以采购 BOM 为准，本轮未重新采集或猜测。

## 通用系统镜像工作站

用户明确：**这个网站将由多个项目共用，不能只定位成 Yikai 专用工具。**
产品入口统一为「系统镜像工作站」，按 **项目 → 设备/系统配置 → 镜像版本** 管理；Yikai Box 是第一个已验证配置。

共用能力：NAS 镜像库、磁盘本体识别、按已用块捕获、校验、恢复、任务记录和交付放行状态。
项目适配内容：目标主板/系统、分区与启动方式、内核/驱动、恢复后的身份处理、该项目验收条件。
项目名只是归属信息，不能代替这些适配与验收。

本轮已实现通用名称、项目归属显示和筛选；镜像接口保留 `project`、`project_name`、`profile`、`version`。
未配置恢复适配的 profile 会被后端拒绝恢复；当前可执行的配置仍为 `seavo-sv3-piper-rt`。其他系统需要验证相应恢复适配后开放。
另有只读历史预览模式：工作站离线时可展示已归档镜像和任务，但不会初始化磁盘执行器，所有写入 API 均拒绝。

当前代码暂留 `XYZBox/imaging_station/`，部署单元、NAS 路径保留原兼容名称；本轮不搬移镜像数据或创建空仓。
后续增加第二个实际项目时，再按稳定接口拆分独立公共项目，避免把 Yikai 的启动/身份处理套给所有系统。
