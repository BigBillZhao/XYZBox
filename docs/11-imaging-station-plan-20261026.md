## 建议架构

- 工作站：轻量 Web 服务、少量镜像元数据与任务日志、受限的本地刷盘执行器。
- NAS：不可变版本镜像、校验清单、来源与最低目标盘容量、恢复记录。
- 数据按块流式传输与压缩，不要求在工作站根盘先缓存完整镜像。
- 第一版只写明确识别的外接目标盘；系统根盘及其父设备排除。
- 恢复前再次核对目标型号/序列号/容量，完成后统一处理 machine-id、SSH 主机密钥、主机名及启动文件。
- 一个硬盘盒足够顺序完成“备份源盘 → 换目标盘 → 恢复”；不能同时进行源盘对目标盘的直拷。

## 离线整理母盘

USB 硬盘盒连接的是外接盘，工作站从另一块内置盘启动，所以可以在工作站运行期间整理外接系统盘。
“离线”指目标 Ubuntu 没有运行；不要求每次都重启到 U 盘。制作块镜像时仍须卸载源分区。

建议先原样备份到 NAS，然后才在梵想盘的挂载目录补入客户 kit、风扇加载配置、桌面说明，清理明确的临时安装器和调试日志。
不直接移动/复制正在使用的 venv：应在目标系统中按固定离线依赖重建客户环境，或保留其经过验证的绝对路径。
尤其不能直接在工作站的 `/media/...` 路径下创建交付 venv；应在目标系统 chroot 内创建 `/home/ubuntu/yikai-box/.venv`，使 shebang/激活脚本指向开机后的真实路径。
原始备份与客户成品镜像各保留一版。每次恢复后重新生成主机身份；NAS 工作站凭据不进入客户镜像。

按已用块复制并不等于自动支持更小硬盘。第一版应明确最低字节数；若要适配不同容量，另做离线收缩与恢复后扩容流程。
现有一次性脚本有固定盘序列号和会话路径，正式 WebUI 需要改成按任务传参及重新确认，不能直接照搬为通用刷盘服务。
ASMedia 硬盘盒的 USB 序列号 `AAAABBBB0010` 在换盘后不会改变；识别源/目标必须读取 SSD 本体序列号，不能只看盒子。
