# Yikai Box 批量部署与产测 MVP

草案 · 2026-10-23 · Codex · 已纳入首轮三条板评

目标：装配、目检完成的 box，装好交付软件后接两条 Piper，开机弹出测试网页。测试员点一次开始，完成使能、运动、回垫、禁能；人工确认通过后，自动移除产测程序，可以出货。失败则保留记录、返工重测。

## 已确定的范围

| 事项 | 当前结论 | 影响 |
|---|---|---|
| D1 出货软件范围 | **交付 Ubuntu 系统与 CAN 驱动/SDK，二次开发由客户完成** | 完整遥操、相机软件不进入交付范围；不额外引入专门 RT 部署要求，产测使用最终交付的内核与驱动 |
| D2 第一版部署方向 | **先把镜像还原到待装的 M.2 SSD，再装入 box** | 母版从实际安装、启动验收通过的系统制作；不把现有 autoinstall/Ventoy 作为本轮依赖。具体烧录设备仍待选 |
| D3 CAN 验收范围 | **只验两路 CAN，分别接两条 Piper** | 四路卡的另外两路不列入首版验收；物理 CAN1/2 与左右臂、系统接口的映射等待本次实测 |

剩余输入：批量台数、同时烧录数、SSD 的 NVMe/SATA 类型与容量，以及两路 CAN 的实际映射。前三项用于选择烧录工作站或专用复制机，映射用于固定工装配置。

## 测试员只做这些

1. 将已还原镜像的 M.2 SSD 装入 box，完成装配和目检；按固定端口标识接两条 Piper、显示器和键鼠。
2. 开机自动进入本机测试网页；开机不运动。
3. 核对机器编号、接线与工装就绪，点击「开始测试」。
4. 程序自动检查 → 使能 → 抬到测试位 → 慢速返回垫上 → 确认禁能。
5. 测试员观察动作，选择「通过并完成出厂」或「不通过」。
6. 通过后保存记录、卸载产测、取消弹窗，显示「可以关机出货」。失败保留测试入口和故障步骤。

两条 Piper 是已知正常的测试工装。首版验证 box 的基本控制链路，不承担机械臂精度标定、寿命或满负载测试。

## 第一版检查范围

| 检查 | 通过条件与失败提示 |
|---|---|
| 软件与驱动 | 交付版本匹配；CAN 驱动已加载且匹配当前内核 |
| CAN 卡 | 识别实际卡型；约定的两路通道存在、已启用且参数正确。四路卡只选用其中两路，不要求其余两路通过产测 |
| 双臂通信 | 两路均收到持续更新的关节/状态反馈；排除本机发送回显；无明显总线错误 |
| 使能 | 两臂各关节确认使能，未报故障 |
| 运动 | 实际关节位置发生预期变化，限时内到位，持续检查反馈新鲜度与故障 |
| 回垫与禁能 | 返回已验收的支撑姿态，确认禁能后才允许人工放行 |

误差、速度和超时先用宽松但有效的阈值，实机定标后固定。报错说明失败步骤和检查建议即可，例如「CAN2 无机械臂反馈，请检查电源、端口与线束」，暂不自动判断坏件归属。

### 两路 CAN 映射待实测

| box 物理端口 | 系统 CAN 接口 | 工装机械臂 |
|---|---|---|
| CAN1 | 待确认 | 左/右待确认 |
| CAN2 | 待确认 | 左/右待确认 |

BigBill 将现场确认本次映射，再写入工装配置、端口贴标和测试报告。旧机的「CAN1 → can0 → 右臂」仅是历史接线，不作为这批机器的默认值；母版首件需重启复核接口映射的稳定性。

## 工装和停止行为

固定底座、垫子位置与支撑高度，现场教出低速的「支撑位 → 测试位 → 支撑位」轨迹，选取能覆盖各关节运动的姿态。首版不开发接触检测或力控；关节到位不能独立证明垫子在位，因此测试员开始前要确认工装状态。

正常结束在支撑位禁能。异常不能一律立即禁能，也不能把退出进程当成停止运动；需在实际 Piper 上验收停止与通信中断行为，并准备现场物理急停。浏览器刷新不能杀掉后台控制；中途重启返回待检查状态，不自动续跑运动。

## 通过后自动清理

软件分为两个独立安装范围：

- **运行包**：Ubuntu 基础系统、已验收内核、CAN 驱动、两路开机配置、SDK 及最小使用说明/示例，保留；客户自行二次开发。
- **产测包**：测试网页、流程、工装轨迹和自动弹窗，放行后卸载。

清理前保存机器编号、镜像/软件版本、已测端口、各步骤结果、时间及人工判定。首版使用本地结构化文件，并提供导出到产线存储或 U 盘的方式，不先建数据库。

清理失败显示「测试通过，待完成清理」，允许重试；返工保留历史结果。重启后已放行机器不再弹窗。需要复测时，由维护入口重新安装产测包。

## 软件安装与分发

当前流程：**实际安装并验收系统 → 安装 CAN/SDK 和产测 → 验证母版 → 捕获镜像 → 在烧录设备上还原到待装 M.2 SSD → SSD 装入 box → 首次启动初始化身份 → 产测。**

BigBill 在首轮评论中确认：此前自动安装方案实机失败，Ventoy 加安装镜像还遇到无法进入安装 GUI 的问题，原因由另一个 session 后续排查。本轮不推断故障根因，也不依赖该方案。另一个 Codex session 正用 SSH＋安装盘安装系统；该系统完成并验收后可成为母版候选，目前不视为已经可用。

CAN 驱动在母版阶段安装并验收，生产现场检查实际加载结果。每版镜像固定软件清单和校验值；母版清除机器特有身份和旧产测状态，首次启动生成本机身份、主机密钥等。磁盘布局按最小目标盘设计；烧录时明确识别目标 SSD 和槽位，排除镜像源盘、工作站系统盘与启动介质。首件必须装回 box，验证实际启动和产测流程。

| 方案 | 能力 | 适用位置 |
|---|---|---|
| **烧录工作站＋Clonezilla＋SSD 转接设备** | 从命名镜像恢复 ext4 已用块，不必对目标机逐台运行 Ubuntu 安装器 | 可先用现有设备试制；SSD 写好后装入 box，转接设备须匹配 NVMe/SATA |
| **智能硬盘复制机** | 部分型号支持已用块复制、镜像管理与日志 | 批量、并行烧录候选；选型需确认接口、管理功能与吞吐 |
| FOG 网络部署 | Web 管理镜像、机器和任务，支持并行/组播部署 | 保留调研结果，本轮不作为主线 |
| 现有 Ubuntu autoinstall/Ventoy | 历史方案存在实机失败和安装 GUI 问题，根因待查 | 单独排障，不作为本轮母版或量产部署的依赖 |

「聪明复制」和「镜像管理」是两项能力，采购时分别核对。U-Reach PE600H 系列列有 ext4 快速复制和源镜像管理，属于可研究的候选；尚未核价或做实盘验证。按已用块复制不代表大盘镜像可直接恢复到任意小盘。

## 开发与验收顺序

1. **工程侧适配 Piper**：复用 XYZBox 的驱动与依赖，确认测试臂固件；待 BigBill 实测两路映射后写入工装配置，适配六轴读取/使能/运动/禁能并验收轨迹。
2. **工程侧接产测网页**：后台状态机、步骤显示、失败记录、人工放行和清理。先把单台完整跑通。
3. **工程侧制镜像，产线试装**：从实际安装验收通过的系统制作母版，完成「离线还原到 M.2 → 装入 box → 首次启动 → 产测」首件验收，再批量复制。

MVP 验收覆盖：正常通过、缺一条臂、反馈中断、运动超时、测试中断重启、清理失败重试，以及通过后再次开机不再弹窗。暂不做复杂诊断、长时间老化、云平台、远程 OTA、机械臂标定或自动刷固件。
